# MPLAD Sentinel — Demo Backend (SIH26102)

AI-powered prototype for detecting anomalies, potential fraud indicators, and
inefficiencies in **MPLADS-style** project implementation.

> ⚠️ **This is a hackathon DEMO, not a production system.**
> All project data used by this backend is **100% synthetic** — generated by
> `data/generate_demo_data.py` — and does not represent real MPs, real
> contractors, or real government records. A risk score means **"this
> project may warrant closer investigation,"** never a confirmation of
> fraud.

---

## What this does

1. Generates ~800–1000 synthetic MPLADS-style projects with intentionally
   injected anomalies (overspend, unusually short/long timelines,
   duplicate/overlapping projects, contractor concentration).
2. Runs four independent anomaly detectors over the data:
   - **Financial** — Isolation Forest on spend patterns
   - **Timeline** — statistical (z-score) anomaly detection on
     category-normalised project duration, plus explicit detection of
     invalid/reversed dates (completion before start)
   - **Duplicate/Overlap** — semantic similarity (Sentence Transformers, with
     a TF-IDF fallback if offline) + geographic distance
   - **Contractor concentration** — NetworkX bipartite graph of
     contractor↔district relationships
3. Combines the four signals into a single 0–100 **risk score** with a
   human-readable explanation and a recommendation.
4. Exposes everything through a FastAPI backend ready to be consumed by a
   Next.js (or any) frontend.

---

## Tech stack

Python · FastAPI · SQLite (via SQLAlchemy — swappable to PostgreSQL) ·
Pandas · NumPy · Scikit-learn · Sentence Transformers (optional) · NetworkX

No Kubernetes, Celery, Redis, or MLflow — kept deliberately simple for a
hackathon demo.

## Setup

### 1. Create a virtual environment (recommended)

```bash
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
```

### 2. Install dependencies

```bash
pip install -r requirements.txt
```

> **Note on Sentence Transformers:** the first time the duplicate detector
> runs, it will try to download the `all-MiniLM-L6-v2` model (~90MB) from
> Hugging Face. This requires internet access on that first run only
> (the model is cached afterward). **If there is no internet access, the
> code automatically falls back to a TF-IDF-based similarity method** so
> the demo still works fully offline — you'll just get slightly less
> nuanced semantic matching (e.g. "Hall" vs "Centre" synonyms are caught
> less reliably by TF-IDF than by real sentence embeddings).

### 3. Run the API

```bash
uvicorn main:app --reload
```

or

```bash
python main.py
```

On the **first run**, the app automatically:
1. Generates the synthetic dataset (`data/projects.csv`) using a fixed
   random seed (`42`) — so results are reproducible across machines.
2. Loads it into a local SQLite database (`data/mplad_sentinel.db`).
3. Runs the full ML pipeline once and caches the results.

This first-run bootstrap can take **30–90 seconds** (mostly model loading /
Isolation Forest fitting on ~1000 rows), after which the API responds
instantly since results are cached in the database.

The API will be live at: **http://localhost:8000**
Interactive API docs (Swagger UI): **http://localhost:8000/docs**

### 4. Regenerating data / re-running the ML pipeline

You don't need to do this manually — it happens automatically on first run.
If you want to force a fresh dataset and re-analysis at any point:

```bash
curl -X POST http://localhost:8000/api/analyze \
  -H "Content-Type: application/json" \
  -d '{"force_regenerate_data": true}'
```

Or just delete `data/mplad_sentinel.db` and `data/projects.csv` and restart
the server — it will regenerate everything from scratch.

To only regenerate the CSV without touching the running server:

```bash
python data/generate_demo_data.py
```

## How the risk score is calculated

Each of the four detectors outputs a 0–100 anomaly score for every project.
These are combined with these weights:

| Signal | Weight |
|---|---|
| Financial | 30% |
| Timeline | 20% |
| Duplicate/Overlap | 25% |
| Contractor concentration | 15% |
| Geographic (duplicate distance) | 10% |

A weighted average alone tends to dilute a single very strong anomaly (one
component at 95 with everything else quiet would only average out to a
MEDIUM score). Since a single severe red flag is still worth investigating
on its own, a **severity bonus** proportional to the single strongest
component score is added on top of the weighted average. Final score is
capped at 100.

- **0–39**: LOW risk
- **40–69**: MEDIUM risk
- **70–100**: HIGH risk

The output never states a project **is** fraudulent — only that it
**warrants investigation**, along with the specific reasons why.

## Connecting a Next.js frontend

CORS is fully open (`allow_origins=["*"]`) for demo convenience. From your
frontend, just point fetch/axios calls at `http://localhost:8000/api/...`.

Suggested frontend pages, mapped to endpoints:
- **Dashboard** → `GET /api/dashboard/summary`
- **Project list / table** → `GET /api/projects`
- **High-risk watchlist** → `GET /api/projects/high-risk`
- **Project detail page** → `GET /api/projects/{id}/analysis`

## Known limitations (by design, for a demo)

- SQLite only (structured so PostgreSQL is a one-line `DATABASE_URL` change
  in `database.py` — no other code needs to change).
- No authentication — add before exposing beyond a local demo.
- Sentence Transformers requires an internet connection on first run to
  download the embedding model; otherwise falls back to TF-IDF.
- Anomaly detectors are fit fresh on the full dataset each time
  `/api/analyze` is called rather than persisted as trained model files —
  intentional for a demo of this size (~1000 rows fits comfortably in
  memory and re-fits in well under a second per detector).
- The intro brief mentions being able to "upload/import" project data, but
  the explicit API endpoint list in the spec does not include an upload
  endpoint, so this build sticks to the 8 listed endpoints plus the
  synthetic generator. Adding a `POST /api/projects/import` (CSV or JSON)
  endpoint would be a small, self-contained addition if you want that
  capability for the demo — happy to add it if useful.
